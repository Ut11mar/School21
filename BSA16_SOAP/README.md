# BSA16 — SOAP-интеграция

## О проекте

Если BSA15 был про REST, то здесь — его более формальный «родственник»: SOAP и WSDL. Задача построена вокруг нового кейса — «Клуб любителей домашних животных» с двумя веб-сервисами, MemberService и PetService, — и вместо проектирования интеграции с нуля выполнено обратное: по готовым WSDL-документам member.wsdl и pet.wsdl восстановлены назначение операций, структура сообщений и требования к разработке.

---

## Что было сделано

Все упражнения собраны в одном файле `SOAP_ex_0005.xlsx`, по листу на каждое:

- `Ex00` — назначение тегов первого уровня WSDL: `<definitions>` как корневой элемент, `<documentation>`, `<types>` со структурами XSD, `<message>` для описания входных/выходных сообщений, `<portType>` с набором операций сервиса и `<service>` с физическим адресом.

- `Ex01` — операции раздела `<portType>` для обоих сервисов: у MemberService — добавление, получение всех, поиск по имени, обновление и удаление члена клуба; у PetService — аналогичный набор операций для питомцев, включая получение питомцев конкретного владельца по его идентификатору.

- `Ex02` — разбор раздела `<schema>`: назначение `<element>` и его атрибута `type`, `<complexType>` как сложного типа из вложенных элементов, `<sequence>` как фиксированного порядка элементов, атрибутов `minOccurs`/`maxOccurs`; отдельно разобрано, что значит отсутствие этих атрибутов (по умолчанию — ровно один раз) и запись `maxOccurs="unbounded"` (массив, как в MemberList и PetList).

- `Ex03` — обратное проектирование по WSDL: для операций `addMember`, `addPet`, `updatePet` и `getAllMembers` восстановлены форматы входных и выходных сообщений — поля, простые типы данных, признаки массива и обязательности. Например, для `addMember` вход — name и email, выход — success и автоматически генерируемый id; для `getAllMembers` выходом служит массив member с id, name и email каждого участника.

- `Ex04` — уточнение к обратному проектированию: описано отличие между `getAllMembers`, возвращающим массив кратких записей всех участников, и `getMemberByName`, возвращающим один полный объект найденного участника.

- `Ex05` — определение endpoint обоих сервисов по данным из WSDL — физические адреса MemberService и PetService.

---

## Итоги

Модуль перевернул привычный процесс: вместо того чтобы писать контракт самостоятельно, требовалось прочитать чужой WSDL как техническую документацию и восстановить по нему намерения разработчика — что делает каждая операция, какие поля обязательны, где скрывается массив, а где — единичная запись. Это ровно тот навык, который нужен аналитику при интеграции со внешней системой, чей контракт уже существует и должен быть понят, а не придуман заново.
