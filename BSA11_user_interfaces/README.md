# BSA11 — Проектирование пользовательского взаимодействия

## О проекте

Проект о том, как функциональные требования (BSA10) превращаются в интерфейс, понятный пользователю. На кейсе «Запись в парикмахерскую» определена форма представления продукта, спроектированы справочники и их экранные формы, построены ключевые сценарии для каждой роли и подробно описаны сами экраны — вплоть до элементов управления и сообщений об ошибках.

---

## Что было сделано

- `ex00_hc.pdf`  
  Выбор формы представления продукта (командная часть проекта).  
  Определено:
  - устройства и форм-фактор — адаптивный веб-интерфейс для ПК, ноутбуков, планшетов и телефонов;
  - тип продукта — корпоративное веб-приложение для сети парикмахерских;
  - способы управления — сенсорный экран, клавиатура, мышь, каналы уведомлений (SMS, Telegram, WhatsApp, VK);
  - требования к локализации — языки интерфейса, часовые пояса, форматы телефонов;
  - специальные возможности — поддержка пользователей с ограничениями, контрастность, работа при разном освещении.

- `ex01_hc.pdf`  
  Экранные формы классификаторов и справочников.  
  В документе:
  - перечень справочников («Услуги», «Категории услуг», «Сотрудники», «Роли сотрудников», «Клиенты», «Расписание мастеров», «Каналы уведомлений», «Отзывы клиентов») со связями между ними;
  - макеты форм списка и карточки для ключевых справочников;
  - основные операции по ролям с условиями выполнения и результатом;
  - вспомогательные операции — сортировка, фильтрация, поиск, сохранение фильтра, дублирование записи, расчёт итогов;
  - правила логирования операций.

- `ex02_hc.pdf`  
  Детализация данных на экранных формах справочников «Услуги», «Сотрудники», «Клиенты», «Расписание мастеров».  
  Для каждого поля указаны:
  - формат представления, обязательность, значение по умолчанию;
  - проверки и тексты сообщений об ошибках;
  - потребности в пагинации, сортировке, фильтрации и поиске с указанием точности совпадения.

- `ex03_hc.pdf`  
  Ключевые сценарии для ролей «Клиент», «Менеджер», «Мастер».  
  Для каждой роли построены:
  - основной сценарий по шагам с целью процесса;
  - схема задач и переходов между ними;
  - ключевой сценарий экранов — от входа до завершения процесса, с возможностью выхода без сохранения.

- `ex04_hc.pdf`  
  Полный список экранных форм системы (SF-01–SF-16) с привязкой к ролям.  
  Для каждого экрана определены:
  - основное назначение и дополнительные действия;
  - необходимые данные и права доступа;
  - сводные таблицы данных по ролям и итоговая матрица доступа «экран × роль».

- `ex05_hc.pdf`  
  Проработка отдельных экранных форм (SF-04, SF-05, SF-07, SF-10, SF-14) — выбор времени, услуги, подтверждение записи, расписание менеджера и мастера.  
  Для каждой формы приведены макет, основные и вспомогательные операции, состав данных и правила журналирования.

- `ex06_hc.pdf`  
  Описание элементов управления на ключевых формах (SF-02, SF-05, SF-07, SF-10, SF-11, SF-14).  
  Для каждого поля указаны тип элемента управления, проверка ввода, сообщение об ошибке и результат при успешном и неуспешном сценарии, а также сводные правила логирования ошибок и операций.

---

## Итоги

Модуль последовательно провёл путь от общей формы продукта до конкретного текста ошибки в конкретном поле. Ключевые сценарии ролей показали, какой путь проходит пользователь к своей цели, список экранных форм связал эти сценарии с конкретными экранами и правами доступа, а детальное описание контролей сделало макеты пригодными для передачи в разработку без дополнительных уточнений.
